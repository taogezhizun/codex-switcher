# Codex Switcher 使用指南

0.4.2 起，Codex Accounts 更名为 **Codex Switcher**。账号、偏好设置和自动更新沿用原位置。推荐通过 App 内“检查更新”升级。安装包和磁盘上的 `.app` 保留旧文件名以兼容已有安装，不需要另装一份。

## 支持范围

macOS 14+、Swift 5.9+ / Xcode 15+。优先在 Apple Silicon 上验证；Intel 可构建，但尚未进行实机验收。

需要安装官方 Codex 桌面 App。工具通过应用标识 `com.openai.codex` 发现 App，支持应用文件名称变化；使用 App 内置的 Codex 可执行程序，不随包再分发 OpenAI 程序。

第一版支持 ChatGPT 登录凭据，以及 `CODEX_HOME/auth.json` 文件认证（默认目录 `~/.codex`）。**暂不支持** API Key、`keyring` / `auto` / `ephemeral` 认证、共享 app-server 守护进程或受管理的认证策略。检测到这些不兼容情况时会停止切换。设置中的认证目录必须与桌面 App 实际使用的一致。

本工具不会自动判断所有正在运行的任务。点击切换后，需要先确认任务已暂停；如果 App 拒绝退出或其已识别的 Codex 子进程仍在运行，则停止切换，不强制结束桌面进程。其他客户端共用同一认证目录时也可能受到影响。

## 从源码构建

在仓库根目录运行：

```sh
./scripts/build-app.sh
open "dist/Codex Accounts.app"
```

将生成的 `.app` 拖入“应用程序”即可自用。脚本使用本地 ad-hoc 签名，无需付费 Apple Developer 账号。它不是 Developer ID 签名或 Apple 公证；其他机器下载未公证产物时可能出现 Gatekeeper 提示。也可以选择从源码在本机构建。

0.4.0 新安装及迁移完成后，账号操作使用本地文件。旧版迁移会主动读取旧钥匙串，详见下方[本地存储与迁移](#本地存储与迁移)。

## 应用内更新

0.3.0 起，点击菜单栏应用菜单或“设置 → 应用更新 → 检查更新…”。发现新版后确认安装，Sparkle 会替换正在使用的工具并重新打开。只重开本工具，账号数据和 Codex 桌面 App 保持原位。0.4.0 在菜单底部显示可用版本，点击“查看更新”打开原生安装窗口；纯提醒不阻塞账号操作，安装窗口打开期间暂停账号操作。

**0.2.x 需要最后手动升级一次**：退出旧工具，把新版本拖到“应用程序”，替换同名 App，之后从同一位置启动。不要从下载压缩包或只读磁盘映像里长期运行。更新采用 HTTPS、Ed25519 签名和提取前校验，签名私钥不在仓库中；它不等于 Apple 公证。0.4.0 迁移完成后不再读取旧钥匙串；升级 App 本身不会自动迁移真实账号。

## 首次使用

1. 在设置中确认桌面 App 和认证目录。
2. 点击“保存当前账号”，保留目前的登录。
3. 点击“浏览器添加账号”，在 OpenAI 官方页面登录另一个自己的账号；添加不会切换当前桌面账号。
4. 暂停桌面中的任务后，选择新账号并点击“切换至此账号…”，核对来源与目标后确认“切换并重开”。
5. 在重新打开的桌面 App 中核对账号，再点击工具中的“已核对，账号正确”；失败时使用“恢复上次认证”。

0.4.1 自动刷新默认开启：启动后刷新所有已保存账号，正常间隔 5 分钟，唤醒后补刷到期账号。最多同时查询 2 个账号，每个账号独立保存结果；无需切换桌面登录。⌘R 刷新选中的账号，“更多 → 刷新全部账号额度”立即刷新全部；进行中可取消，已完成的结果会保留。登录、切换、待核对和应用更新期间暂停刷新，设置中可关闭自动刷新。

网络等临时错误按 10、20、40、60 分钟退避，成功后恢复 5 分钟。检测到凭据过期或服务请求重新认证时，该账号显示“需要重新登录”并暂停自动刷新，保留上次额度和时间。通过浏览器重新添加同一账号即可更新凭据；当前账号也可在 Codex 重新登录后保存。当前登录文件出现新凭据时，会自动尝试恢复查询。尚未完成旧钥匙串迁移时，仍只刷新当前账号。

额度查询使用隔离辅助进程和 externally managed token 模式，不在第二个进程中刷新保存的 refresh token。当前账号优先使用 Codex 最新登录文件，其他账号使用本地保存的凭据；写回前再次核对来源、账号和凭据是否发生变化。凭据失效后不会自动打开浏览器或轮换 refresh token。工具不会发送预热消息、消费额度重置券或进行自动轮换。

## 本地存储与迁移

以下描述适用于 0.4.0 起的文件存储实现（首次公开发布于 0.4.1）。新安装直接使用本地文件；从 0.3.x 升级时显示“迁移已保存账号”，不会在启动时读取钥匙串。

1. 点击“查看迁移说明”，了解文件存储后选择“开始迁移”。迁移读取本工具的旧账号与恢复记录，可能出现一个或多个系统授权弹窗。
2. 工具核验所有账号、备注、缓存和恢复备份后一次性启用新存储。取消授权、数据损坏或写入失败不会启用部分结果，可修复后主动重试。
3. 选择“稍后”仍可查看账号、刷新当前额度及更新 App；保存、添加、移除、切换和恢复等凭据操作需先完成迁移。
4. 成功后正常账号操作不再访问钥匙串。旧钥匙串记录和旧元数据保留，但不再读写；后续账号变化不会同步回旧版，请勿降级或同时运行旧版。

数据文件为 `~/Library/Application Support/CodexAccounts/local-store-v1.json`：包含完整登录凭据、账号元数据、额度缓存和恢复备份；目录 0700、文件 0600，使用原子替换。凭据仅做 JSON/base64 编码，**不是加密**。同一 macOS 用户运行的其他程序也可能读取，应用不会主动上传；系统备份是否包含它由备份设置决定。

文件存储下，重启会读回本地恢复记录；发现待核对切换时，先核对或恢复，再继续切换和刷新。损坏的本地库不会回退读取旧钥匙串。

## 钥匙串与授权

0.3.2 将钥匙串访问限制在主动账号操作；0.4.0 进一步改为仅在明确开始旧数据迁移时读取本工具的旧记录。迁移完成后的日常操作无需这类授权。Apple 未公证应用的首次打开提示和 OpenAI 浏览器登录是另外的流程。

## 日常操作

状态栏默认显示原创图标与当前已保存账号的剩余比例，例如 `74%`。取 Codex 各周期中最低的剩余比例，悬停查看所选周期及更新时间；其他额度池不参与这个数字。没有匹配账号、未知额度或切换待核对时显示 `—`；过期或失败缓存显示 `~74%`。可在“设置 → 外观与隐私”关闭百分比。数据随当前身份识别和现有刷新调度更新，不为状态栏额外发起请求。

菜单栏点击目标账号即可就地确认切换；当前认证置顶，点击它可打开桌面 App。账号列表支持滚动和搜索，不限于前五个账号。菜单账号行显示“剩余 43% · 9 月 24 日 15:30 重置”和进度条，按系统当前时区与时间格式显示。周期、距重置时间、套餐和上次查询时间放在悬停提示中，VoiceOver 也可读取。过期或失败缓存标为“上次剩余”；需要重新登录的账号单独标记。接口没有返回重置时间时不推算，重置时间已到时等待查询确认。摘要取 Codex 各周期中最低的剩余比例；没有 Codex 数据时显示未读取，不借用其他额度组。

额度详情优先显示接口的易读名称，Codex 排在前面。未知组默认折叠到“其他额度”，原始编号可点击 ⓘ 查看。不同组不能合并或视为可互相替代。旧缓存可直接使用；刷新后可获得接口提供的新名称。

| 快捷键 | 操作 |
| --- | --- |
| ⌘N | 浏览器添加账号 |
| ⌘R | 刷新选中的账号额度 |
| ⌘↩ | 查看选中账号的切换确认 |
| ⇧⌘P | 隐藏或显示邮箱 |
| ⌘E | 编辑选中账号的备注 |

隐藏邮箱不等于可安全公开截图：备注仍然可见。公开素材始终使用演示模式。
